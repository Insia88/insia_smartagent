# 채널 가이드: 네이버 블로그 (`naver_blog`)

검색으로 들어온 독자가 "찾던 답이 여기 있다"고 느끼고, 끝까지 읽은 뒤 이웃추가나 문의로 이어지게 만드는 글이다.

## 1. 독자와 목적

- 독자: 네이버에서 메인 키워드를 검색한 사람. 대부분 모바일에서 읽고, 첫 화면에서 답이 안 보이면 바로 뒤로 간다.
- 목적: 검색 의도에 바로 답하고, 직접 해 본 사람만 줄 수 있는 구체 정보로 신뢰를 쌓는다.

## 2. 네이버 검색에 대해 알려진 것 (2026-09-28 확인)

- 공개 자료에서 확인되는 설명은 개념 수준이다. C-Rank는 블로그 단위로 주제 전문성과 누적 신뢰도를 보고, D.I.A.(D.I.A.+)는 문서 단위로 검색 의도 적합도, 작성자의 경험, 정보 충실성, 독창성 등을 반영하는 모델로 널리 설명된다.
- 네이버는 두 모델의 계산 방식과 가중치를 공개하지 않았고, 이번 확인에서 네이버 공식 원문은 직접 열람하지 못했다. 그래서 아래는 규칙이 아니라 **권장사항**이다.
  - 한 블로그가 한 주제를 꾸준히 다루는 것이 유리하다고 보고, 브랜드 주제와 맞는 키워드를 고른다.
  - 복사·짜깁기 문서, 키워드만 반복하는 문서, 홍보 문구로만 채운 문서는 피한다.
  - 직접 경험, 과정, 수치, 사진 같은 고유 정보를 넣는다.
- 태그 개수 5~10개는 이 시스템의 운영 기준이다(플랫폼 한도가 아님).

## 3. 출력 형식 (코드가 검사함)

- `title`: **공백 포함 40자 이하**, 메인 키워드(`brief.keywords[0]`)를 그대로 포함(띄어쓰기 차이는 허용). 가능하면 앞쪽에 둔다.
- `content`: 마크다운. 제목을 본문에 다시 쓰지 않는다(`#` 제목 줄 없음).
  - 도입부: 소제목 없이 2~4문장. 첫 문장에서 검색 의도에 답한다.
  - 소제목: `## ` 로 시작하는 줄 **3개 이상**. `###`는 개수에 들어가지 않는다.
  - 이미지 자리: `[이미지: 무엇을 보여 줄지]` **3개 이상**. 어떤 사진·캡처·도표인지 구체적으로 쓴다.
  - 분량: **공백 제외 1,500~3,000자** (출처 줄, 이미지 자리 문구 포함).
  - 마무리: `## ` 소제목 아래 요약 2~3줄 + 행동 유도(이웃추가, 댓글 질문, 문의 방법).
  - 출처: 사실·수치를 썼다면 본문 맨 끝에 `출처:` 줄을 출처마다 하나씩.
- `hashtags`: **5~10개**, 각각 `#` 포함, 띄어쓰기 없이(`#AI마케팅자동화`). 본문 안에는 태그를 쓰지 않는다.

```markdown
AI 마케팅 자동화를 처음 알아본다면 ... (검색 의도에 바로 답하는 2~4문장)

[이미지: 도입부 대표 이미지. 노트북 앞에서 채널별 초안을 비교하는 화면]

## 1인 창업자가 AI 마케팅 자동화로 줄일 수 있는 일
짧은 문단 2~3개 ...

[이미지: 주간 콘텐츠 작업 전·후 비교 표]

## 도입 전에 꼭 확인할 3가지
...

## 직접 써 보며 알게 된 점
...

[이미지: 검수 체크리스트 화면 캡처]

## 정리하면
- 요약 1
- 요약 2
궁금한 점은 댓글로 남겨 주세요. 이웃추가하면 다음 글(○○)을 먼저 볼 수 있어요.

출처: 중소벤처기업부, 「○○ 실태조사」(○○년 기준)
출처: ○○연구원, 「○○ 보고서」(○○년)
```

(예시의 ○○ 자리에는 리서치 팩에 있는 실제 기관·자료명·기준시점만 넣는다.)

## 4. 문체와 가독성

- 해요체(~해요, ~이에요)로 통일한다. 설명은 친근하게, 사실은 정확하게.
- 문단은 1~3문장. 모바일 한 화면에 문단 2~3개가 보이는 정도.
- 소제목은 내용 라벨보다 독자가 얻는 답으로 쓴다: "기능 소개" 대신 "하루 30분을 되찾는 작업 3가지".
- 메인 키워드는 제목, 도입부 첫 두 문장, 소제목 1~2개에 자연스럽게 넣는다. 본문 전체 4~6회 정도가 적당하다(경험칙). 같은 문장에 반복하지 않는다.
- 직접 경험은 브리프·리서치 팩에 있는 것만 쓴다. 없으면 `[대표 경험 추가: 처음 콘텐츠를 만들 때 걸린 시간]`처럼 자리표시로 남긴다.
- 수치는 문장 안에서 기관과 시점을 밝힌다: "중소벤처기업부 조사(○○년 기준)에 따르면 …".

## 5. 검수 루브릭 (합계 100)

| id | 항목 | 배점 | 보는 것 |
|---|---|---|---|
| `search_intent` | 검색 의도·키워드 | 20 | 메인 키워드가 제목·도입부·소제목에 자연스럽고 검색 의도에 답하는가 |
| `originality` | 경험·독창성 | 20 | 직접 경험·고유 정보·구체 사례가 있는가 (복붙형 정보글이 아닌가) |
| `readability` | 가독성 | 20 | 짧은 문단, 소제목, 이미지 자리로 모바일에서 읽기 쉬운가 |
| `accuracy` | 정확성·출처 | 20 | 사실 주장이 리서치 팩과 일치하고 출처가 표기되었는가 |
| `cta` | 마무리·행동 유도 | 10 | 요약과 이웃추가·댓글·문의 등 다음 행동이 명확한가 |
| `format` | 형식(자동) | 10 | 분량, 소제목 수, 이미지 자리 수, 태그 수, 제목 길이·키워드 (코드 채점) |

## 6. 제출 전 체크리스트

- [ ] 제목 40자 이하, 메인 키워드 포함
- [ ] 도입부 첫 문장이 검색 질문에 대한 답이다
- [ ] `## ` 소제목 3개 이상, `[이미지: …]` 3개 이상
- [ ] 공백 제외 1,500~3,000자
- [ ] 수치마다 기관·기준시점, 끝에 `출처:` 줄
- [ ] 마지막 소제목에 요약 + 행동 유도
- [ ] 태그 5~10개가 `hashtags`에만 있고 본문에는 없다
- [ ] 과장·확정 표현("무조건", "100% 효과", "보장")이 없다

## 7. 하지 말 것 / 할 것

- 하지 말 것: 키워드 나열형 문장, 다른 글을 바꿔 쓴 듯한 일반론, 가짜 후기·고객 사례, 외부 링크 여러 개, 이미지 없이 긴 글.
- 할 것: 검색자가 다음에 궁금해할 질문을 소제목으로 미리 답하기. 표나 체크리스트를 이미지 자리로 제안하기. 광고성 글이면 마지막에 "직접 운영하는 서비스 소개 글"임을 밝히기.

## 8. 예시

제목 (메인 키워드 `AI 마케팅 자동화`)
- `AI 마케팅 자동화, 1인 창업자가 먼저 정할 3가지` (공백 포함 26자)
- `1인 창업 3년 차가 써 본 AI 마케팅 자동화 체크리스트` ← 경험이 사실일 때만

도입부
- 나쁜 예: "요즘 AI가 정말 핫하죠? 오늘은 AI 마케팅 자동화에 대해 알아보겠습니다."
- 좋은 예: "AI 마케팅 자동화는 글을 대신 써 주는 도구보다, 조사와 검수를 맡기는 쪽에서 시간이 더 줄어요. 혼자 채널 세 개를 운영한다면 이 순서로 도입해 보세요."
