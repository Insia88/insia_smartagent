# 샘플 실행 기록

이 폴더에는 샘플 브리프(`brief.json`) 하나로 INSIA의 3-에이전트 파이프라인을 실제로 돌린 기록이 들어 있습니다.

- **리서치 에이전트**가 2026년 9월 28일 웹에서 자료를 직접 찾아 열어 보고 확인했습니다.
- **총괄 에이전트**가 그 리서치 팩만 근거로 채널별 초안을 썼습니다.
- **검수 에이전트**가 초안마다 따로 채점하고 이슈와 사실 확인 결과를 남겼습니다.
- 80점 미만이거나 critical 이슈가 있으면 총괄 에이전트가 수정본을 다시 썼습니다(최대 2회).

## 채널별 점수

| 채널 | R0 (첫 초안) | R1 (수정본) | 결과 |
|---|---|---|---|
| 사업계획서 | 65 | 81 | 1회 수정 후 통과 |
| 네이버 블로그 | 72 | 83 | 1회 수정 후 통과 |
| 링크드인 | 80 | - | 첫 초안 통과 |
| 인스타그램 | 83 | - | 첫 초안 통과 |

통과 기준은 100점 만점에 80점 이상이면서 critical 이슈가 없는 것입니다. 점수는 루브릭 항목의 합계이고, 그중 형식 10점은 코드가 자동으로 채점합니다(`channels.check_format`). 여기 있는 초안 6개는 모두 형식 검사를 통과합니다.

## 리서치 팩

`research.json`에는 출처 34개가 있습니다.

| 신뢰도 등급 | 뜻 | 출처 수 |
|---|---|---|
| Tier 1 | 정부·공공기관 원문, 플랫폼 공식 문서 | 19 |
| Tier 2 | 언론, 리서치기관 | 14 |
| Tier 3 | 기타(SNS 게시물 등) | 1 |

이 출처로 확인한 사실(findings)은 30개(신뢰도 high 17, medium 13)이고, 찾지 못했거나 확인하지 못한 부분은 gaps 33개로 따로 적혀 있습니다.

## 파일 구성

```
brief.json                 입력 브리프
plan.json                  계획: 핵심 메시지 5개, 리서치 질문 5개, 채널별 목차
research.json              리서치 팩: findings, sources, gaps
drafts/<채널>.r<N>.json     초안 (r0 = 첫 초안, r1 = 수정본, change_log에 고친 내용)
reviews/<채널>.r<N>.json    검수: 루브릭 점수, 이슈, fact_checks, 요약
```

채널 이름은 `bizplan`(사업계획서), `naver_blog`, `linkedin`, `instagram`입니다.

## mock 모드로 재생하기

API 키 없이 이 기록을 그대로 다시 볼 수 있습니다.

```bash
python -m insia_agents run --brief examples/sample-run/brief.json --mode mock
```

브리프 주제가 이 폴더의 `brief.json`과 같으면 mock 백엔드가 계획, 리서치, 초안, 검수를 이 파일들에서 읽어 실제 실행과 같은 순서로 보여 줍니다. 기다리지 않고 결과만 보려면 `--speed 0`을 붙이세요. 녹화된 검수도 재생할 때 형식 검사를 다시 거치므로, 형식 점수는 늘 현재 코드 기준으로 계산됩니다.

## 기록 정정

녹화 스크립트에는 쿼리 문자열만 다른 URL을 같은 출처로 합치는 버그가 있었습니다. 이 때문에 중기부 보도자료 여러 건과 기업마당 첨부 파일(사업계획서 양식, 질의응답)이 각각 s1과 s18 하나로 합쳐졌고, 일부 수치가 실제로 확인한 문서가 아닌 다른 문서에 인용돼 있었습니다. 검수가 끝난 뒤 출처를 다시 합쳐 바로잡았습니다.

- s1~s25는 id와 URL이 그대로이고, 빠졌던 출처 9개를 s26~s34로 되살려 f2·f3·f4·f11·f20·f23·f24의 출처를 바로잡았습니다.
- 초안의 인용(`[s#]` 표지, 사업계획서 참고자료 목록, 블로그 출처 줄)과 검수의 `fact_checks[].source_ids`를 새 번호에 맞췄습니다.
- 인용을 고치면서 본문 일부와 분량도 바뀌었습니다. 인스타그램 캡션의 16.3% 출처를 플래텀 보도로 밝혔고, 사업계획서 참고자료 목록이 늘었습니다.
- 마지막 원문 대조에서 두 곳을 더 고쳤습니다. 사업계획서 R1의 '입문 단계' 정의 문장은 인용한 기사(s6)에 없어서 지웠고, 인건비 기준의 참고 사이트는 질의응답 원문(s31)대로 '임금직업포털(wagework.go.kr)'로 바꿨습니다.
- 검수 점수, 이슈, 요약은 기록된 그대로 두었고 형식 검사 값만 현재 본문으로 다시 계산했습니다(점수 변화 없음). 그래서 이슈 문장에 나오는 글자 수와 인용은 정정 전 초안을 두고 한 말입니다(예: 사업계획서 R1 검수의 "[s18] 하나로 공고문·질의응답·양식을 인용" 지적).
- f15(국내 AI 산업 매출)에서는 보도 기사의 2023년 값과 증가율이 서로 맞지 않아 이 두 값을 뺐습니다. 사업계획서 R0에는 '전년 대비 12.5% 증가'가 남아 있지만 첫 초안의 기록이라 그대로 두었고, R1은 이 값을 쓰지 않습니다.

## 쓰기 전에 꼭 확인할 것

- 이 폴더는 파이프라인이 어떻게 도는지 보여 주는 예시입니다. 여기 있는 글을 그대로 게시하거나 제출하지 마세요.
- `[대표자 성명]`, `[대표 경험]`, `[문의 방법]`, `[확인 필요: …]`, `[○]` 같은 자리표시는 사람이 채워야 합니다. 사업계획서 제출본에서는 성명 같은 개인정보를 ○나 *로 가려야 합니다.
- 게시하거나 제출하기 전에 사람이 모든 수치의 원문 출처를 직접 열어 확인해야 합니다. 특히 언론 보도로만 확인한 Tier 2 수치는 원 보고서와 대조하세요. 자료는 2026년 9월 28일 기준이라 그 뒤에 바뀐 내용은 반영되어 있지 않습니다.
